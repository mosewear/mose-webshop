# Shopify inventory evidence

This staged change reads Shopify inventory into a separate service-only evidence table. It does not transfer stock, modify Shopify quantities, change local `product_variants.stock_quantity`, release a mapping, or enable checkout. The legacy inventory ledger and historical payment processing remain separate until the approved cutover.

Apply `20261028000100_shopify_inventory_evidence.sql` only after the pilot schema is installed and the migration is reviewed. Map each released variant to its verified Shopify `inventory_location_id`; do not infer a location from its display name or aggregate product stock. MOSE-owned inventory requires a cutover count/transfer and a verified MOSE location before `inventory_verified` may be set by the release procedure. This worker does not certify that initial transfer.

The separate `/api/cron/shopify-inventory` runner defaults to a no-op. Both `SHOPIFY_SYNC_ENABLED=true` and `SHOPIFY_INVENTORY_SYNC_ENABLED=true`, plus a valid `CRON_SECRET`, are required. The scheduled runner processes at most two location batches of 50 variants every five minutes, independently of the order worker. Capacity is bounded; if a larger catalog or many locations cannot refresh within 15 minutes, increase proven capacity before release. Missing/stale evidence blocks checkout rather than extending freshness.

Each location batch uses Admin API 2026-10 with `read_products`, `read_inventory`, `read_locations` and the shop currency field's `read_markets_home` access. The operation validates against that schema. Production uses the configured offline Admin token, never a browser/CLI token. Read Shopify's [InventoryItem reference](https://shopify.dev/docs/api/admin-graphql/2026-10/objects/InventoryItem) for tracked inventory and location-specific levels.

Only a tracked variant with DENY inventory policy, ACTIVE product, exact product/variant identity, expected EUR price, and an explicitly configured active online-fulfillment location can produce a known quantity. The evidence uses `available`, excludes `on_hand`/incoming/other locations, and treats negative availability as zero. Untracked Tapstitch/ODMPOD quantity `9999999` is a supplier sentinel: availability remains unknown and quantity is null. No supplier location, sample, publication or fulfillment confirmation is inferred by this process. An unavailable quantity source needs a separate verified supplier capability before those variants can be released.

Claims use short recoverable leases. Mapping edits change a revision, invalidating prior evidence and in-flight writes. Completion checks the lease and revision transactionally; replayed/expired writes cannot replace newer evidence. Provider/schema failures replace prior known evidence with a sanitized error, not a stale success. Missing location mappings require no provider call and produce unknown evidence.

Checkout validates current evidence before provider work, attempt reservation, or checkout-URL reuse; it still performs its existing live Storefront stock/price check and Shopify remains responsible for final checkout stock enforcement. Evidence must match both the current mapping and the exact mapping revision loaded to authorize that checkout, be at most 15 minutes old, and cover the requested quantity. Admin readiness checks the entire released mapping set, including zero-stock variants, without treating a manual inventory gate alone as sufficient.

Local verification: `npm test`, TypeScript, lint, production build; `MOSE_PGLITE_MODULE=/absolute/path/to/@electric-sql/pglite/dist/index.js node tests/lib/shopify-inventory-migration-check.mjs` tests permissions, unknown-quantity constraints, location isolation, leases, mapping revisions and default-off gates against local PostgreSQL only. No live database is used by that test.
