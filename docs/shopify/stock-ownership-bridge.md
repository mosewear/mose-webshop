# Staged legacy paid-stock bridge

This code is disabled by default. It does not transfer the 119 observed local units, create ownership rows, activate products, obtain write scopes, or enable a cron. The approved read-only Shopify app cannot execute this worker until a separate `write_inventory` grant is approved.

`LEGACY_INVENTORY_ATOMIC_ENABLED=true` routes paid legacy MOSE orders through service-only `apply_legacy_paid_stock(uuid)`. That RPC locks the paid order and all affected variants in stable order, aggregates duplicate variant/presale lines, updates every quantity and `stock_decremented_at` in one transaction, and replays the stamp without decrementing again. Failed lines roll the transaction back. Unknown RPC outcomes never fall back to old non-atomic client writes.

No ownership rows means legacy stock remains local. Before creating a `shopify_stock_ownership` row, freeze the relevant sales/writers, reconcile paid and pending/late legacy payments, transfer the reviewed quantity to the verified native Shopify item/location using a separately reviewed compare-and-swap request, read it back, and record the actual cutoff and verification reference. Do not copy an old observation. The ownership trigger takes the same variant lock as paid inventory processing. Pending/uncertain remote deltas pin the ownership route against update/delete.

After explicit ownership transfer, a historical order created before that variant's cutoff atomically records one durable negative Shopify `available` delta together with its local shadow update and stamp. It does not overwrite Shopify quantities. The outbox freezes item/location/generation and uses its durable UUID as Shopify's `@idempotent` key. New legacy orders after the cutoff and presale ownership are rejected. A local shadow shortfall stays visible and must be reconciled, even if the remote delta succeeds.

`SHOPIFY_SYNC_ENABLED=true`, `SHOPIFY_LEGACY_STOCK_SYNC_ENABLED=true`, and `LEGACY_INVENTORY_ATOMIC_ENABLED=true` are all required for the authenticated `/api/cron/shopify-legacy-stock` runner. It drains at most five fenced events within 90 seconds. Add its five-minute Vercel schedule only alongside reviewed release configuration. Provider timeouts retry the exact key/variables. Eight failures dead-letter. Uncertain requests older than 22 hours dead-letter rather than replay beyond Shopify's documented 24-hour idempotency retention. Never reset keys or clear unknown outcomes without provider reconciliation.

Public checkout readiness must require `legacy_stock_bridge_health()` pending/deadLetters/shortfalls all zero (and measured fresh sync health), not merely a broad inventory flag. When an adjustment is newly queued, the public checkout must fail closed until it is confirmed. Inventory snapshot evidence must be refreshed after bridge delivery; an earlier snapshot does not include the delta.

Still required for global cutover: apply the reviewed migrations, set the explicit return-stock cutoff, populate reviewed ownership/item mappings, freeze and reconcile pending/late legacy payments during the actual stock transfer, approve production write scope, and verify live worker, mirror and admin/return scenarios. The staged guards and command journal below protect every local stock writer once ownership changes. A private supplier-only sample checkout does not need the merchant-stock transfer and must not mark physical sample quality verified.

Validation: local PGlite transaction/rollback/replay/presale/lease/privilege tests; Vitest stable-key, unknown outcome, ownership mismatch and lost-ack tests; TypeScript and ESLint. No live stock mutation was run.

References: [inventoryAdjustQuantities 2026-10](https://shopify.dev/docs/api/admin-graphql/2026-10/mutations/inventoryAdjustQuantities), [Shopify idempotency retention](https://shopify.dev/docs/apps/build/apis/graphql-admin/implementing-idempotency).

## Administrative changes and shadow mirror

Migration 009 now retires the live historical `pending`→`paid` status trigger inside the migration transaction. That trigger ignored the paid-order stock stamp and could decrement a second time. Preserve the reviewed trigger definition in rollback evidence. Apply only after the compatible app version is deployed; the ordinary legacy client decrement still works while the new atomic flag is off.

Once a variant has an ownership row, a database trigger blocks uncontrolled local regular/presale quantity writes. New authenticated `apply_inventory_command(operation UUID, kind, payload)` calls the existing admin check and inventory audit/receipt RPCs under a command journal. Adjustment, receipt and received-return commands commit local shadow changes and the positive/negative provider delta together. Duplicate delivery lines are aggregated; operation replay returns the saved result; reusing an operation for different content fails. Presale adjustments for Shopify-owned variants are explicitly rejected. Existing direct order creation/decrement/product editing paths cannot quietly overwrite a Shopify-owned quantity.

The admin inventory browser helper persists a hash and operation UUID across failed/unknown requests, including reloads, and only clears it after a valid confirmed response. Notes and receipt/product contents are not persisted by this helper. Admin adjustment/receipt routes require that UUID only when the atomic flag is enabled. Legacy return receipt uses the return UUID and validates quantities/variants against that return's original order inside the database; retries preserve an already-refunded return's status. A stock retry warning does not suppress the retail refund; an unconfirmed stock command returns HTTP 503 so it remains visible and can be retried.

`mirror_owned_shopify_stock` is service-only and also runs after inventory snapshot updates. It requires enabled MOSE-owned mapping with the same Shopify variant, inventory item and location, a fresh known current revision, observed after cutoff and every processed adjustment, and zero pending deltas. Only then does it update the local shadow without queueing another adjustment. Populate both the reviewed mapping's `inventory_item_id` and ownership's `shopify_variant_id`; missing evidence fails closed.

`legacy_stock_bridge_health()` returns `pending`, `deadLetters`, `shortfalls`, `oldestPendingAt`, `expectedOwnershipCount`, `verifiedOwnershipCount`, `lastWorkerAt`, and `returnStockCutoverReady`. Verified ownership additionally requires the local shadow to equal the fresh provider snapshot and no presale balance. A successful, error-free worker run records a heartbeat through service-only `mark_legacy_stock_worker`. Global readiness must require full expected ownership coverage, fresh heartbeat, no pending/dead-letter/shortfall, and the normal inventory snapshot gates. Empty queues alone do not establish cutover.


Absolute edits in the inventory grid additionally freeze the displayed expected quantity and target quantity. The local command rejects an already-stale view; the Shopify worker uses idempotent `inventorySetQuantities` with `changeFromQuantity` rather than converting that edit into a blind delta. A provider compare failure immediately dead-letters for reconciliation; it never updates the expected quantity and retries a different intent automatically. Relative adjustments, receipts and returns continue to use deltas. The admin confirmation explicitly indicates when provider synchronization is pending.

The return-stock cutoff defaults NULL and therefore blocks new atomic restocking until deliberately set at activation. Historical received/refunded returns without reviewed ledger evidence require reconciliation; they are never silently restocked again. The per-order-item return ledger caps cumulative restocked quantity and serializes concurrent partial returns. Two legitimate post-cutoff partial returns can be processed independently. Empty or malformed return item lists are rejected.
